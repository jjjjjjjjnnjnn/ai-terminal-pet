## 2. 为什么说 npm 那 4,586 是机器流量

三条独立证据，任意一条都足以否掉"真人下载"这个解释：

1. **不可安装的版本也被下载了 166 次。** `0.0.0-stage` 是 npm 发布后头几分钟的占位版本，
   没有文档、没有可解析的依赖、装上去什么也不是。真人不会下载它 166 次。
2. **分布是平的。** 25 个版本各 137–227 次，与"哪个是 latest"无关。真人安装会压在 latest 上，
   旧版本只剩少量固定版本号的人。
3. **同类包呈现出完全相反的形状。** `dsh-pet` 一周 86,416 次里 **58%** 落在最新两个版本上，
   旧版本只剩个位数到几十。这才是人。

`latest share` 因此是本项目唯一值得盯的 npm 派生指标：

```
latest share = 最新两个版本 的下载 / 全部版本 的下载
  爬虫队形 ≈ 3–10%      真人 ≈ 50%+
```

它与"版本数"无关，所以**发版越多，分母越大，指标只会更难看**——这正是它诚实的地方。

## 3. 所以现在的真实状况

- **外部用户数：0（可观测范围内）。** 零 issue、零 fork、零外部 star、安装资产等于自查基线。
- **已经做对的事仍在**：工程可复现、门禁齐全、三平台可跑、目录条目在位、npm/git/Release 三条安装路径都通。
  这些是"来了人接得住"的前提，不是"会有人来"的原因。
- **差距不在质量，在可见性、安装摩擦与叙事**（§4–§5）。

把它写成零不是自贬：本仓库所有对外数字都要求可证明，那么"没有用户"也必须先被承认，
否则后面任何增长都无法与噪声区分。

## 5. 三个瓶颈（按证据强度排序）

1. **可见性（最强）**：14 天 11 个唯一访客。任何转化优化在这样的分母上都无法被测量。
2. **安装摩擦**：我们的路径是「装应用（未签名 exe，SmartScreen）+ 接上报端」；
   `dsh-pet` 的路径是「装一个插件，右侧就出现一只宠物」。winget 合并前，Windows 用户还要跨过一道系统警告。
3. **叙事**：我们卖的是"谁在等你"（信息），首屏却是长文档与验证表；竞品卖的是"宠物"（情绪），首屏是 GIF。
   搜索词也印证：想找宠物的用户不会因为读到"499 个测试"而留下。

### P1 — 转化（我做，1–2 天）

### P3 — 发版节奏（我做）

近 7 天：**222 个提交、53 个 release**（32 个 DSH + 21 个浮窗）。后果有三，且都有代价：

- 每次发版都新增一个 npm 版本 → 爬虫多抓一次 → 总量虚高、latest share 更低；
- 每个版本都要完整走一遍 tag/资产/npm/上游 PR，时间成本线性增长；
- 上游目录 PR 一天换一条，容易被维护者当成噪声。

**处理**：改成"批次发版"——同一主题的改动攒成一次发布（建议每周 ≤ 2 次），
安全/回归修复除外。这条要写进 `AGENTS.md` 的发版规矩。

### P4 — 定位决策（你定，我给数据）

| 路线 | 竞品与量级 | 需要的投入 | 风险 |
|---|---|---|---|
| **A. 状态带（现状）** | `agent-notifications` 833★ | 小：继续做深"谁在等、等了多久、一键回去" | 市场更小；用户不主动传播 |
| **B. 加人格（宠物化）** | `dsh-pet` 6.4k★ / `clawd-on-desk` 6.7k★ | 大：动画/美术/素材包；首屏 GIF 与人格设定 | 我们入场晚；"宠物"审美是主观竞争 |
| **C. 双轨**：状态带为骨架，加一层可选动画与"宠物包" | 两者人群都覆盖 | 中：先做 3 个状态动画 + 一个素材目录 | 需要明确不破坏"56 px 信息密度"的取舍 |

**我的建议**：先做 **A 的收口 + C 的最小版本**（3 个状态动画、可关），不要一步跳到 B。
理由：4.7 MB、无运行时、四终端聚合、点行回终端这几条是 A 的真实差异；
人格是放大器，不是替代品——但放大之前必须先有人看到（P1–P2）。
